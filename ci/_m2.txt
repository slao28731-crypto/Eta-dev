fix(terminal): 修复 AndroidNdkInstaller 少闭合一层 use{}（run #40 编译失败）

## 根因

extractArchive 里的三层 `use { ... }` 嵌套：
  archive.inputStream().use { raw ->
    ... archive.inputStream().buffered().use { stream ->
      ... TarArchiveInputStream(compressed).use { tar ->
        while (...) { ... }

只闭了两层就结束，`use { tar ->` 的右括号丢失。后果是整个 class 从
第 206 行起被提前截断，之后的 companion 常量、嵌套 data class 全部
被当成顶层声明，编译报了几十条：

  Unresolved reference 'ROOT_DIR_NAME'
  Unresolved reference 'InstalledNdk'
  Unresolved reference 'ExtractProgress'
  Unresolved reference 'ACTIVE_POINTER'
  Unresolved reference 'readNdk'
  ...（共 20+ 条）

真正的根因只有一个「}」。

## 为什么原有检查没抓到

ci/static_check.py 的「括号平衡」只比较 `{` 与 `}` 的数量差。这次事故里
同一处缩进错位让数量恰好接近，差值没能暴露断点位置；而「声明顺序校验」
看到的是文本层面的顺序，也看不出 class 已被截断。

## 新增检查（真能拦住这一类）

ci/static_check.py 新增 [3/5]「花括号深度归零」：
逐字符扫描（跳过注释/字符串/字符常量/raw string），要求每个文件
最终 depth == 0。少一个 `}` 就是 -1，多一个就是 +1，都能立刻定位。

配套 ci/self_test_static_check.py 扩成两个事故的自测：
1. run #37 的未转义 `$eta_bin` → 必须报错且指向 eta_bin
2. run #40 的少闭合一层 use{} → 必须报错且来自深度检查
并从「只查 3 个文件」扩到 4 个（把 AndroidNdkInstaller.kt 纳入常规检查）。

## 验证

- 六项 CI 校验脚本本地全过
- 自测确认两个事故注入后都会被拦下
- 深度扫描：AndroidNdkInstaller.kt 现为 depth=0
- 编译结果以 CI 为准
