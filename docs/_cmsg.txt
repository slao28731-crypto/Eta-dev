feat(runtime): 第 1 批并发改造——多 run 会话 + 主任务浮层

根因（P096）：AgentRuntimeService 只有单个 activeSession，且 startRun()
第一行就 cancel()，所以一条对话发消息会掐死另一条。

Service 侧：
- 删掉 activeSession 字段，改为 activeSessions: ConcurrentHashMap<runId, Session>
- 新增 primaryRunId：浮层（胶囊/暂停/补充指令）只能对应一个 run，
  约定「谁是主任务谁上浮层，其余安静跑」。没有主任务时新 run 才接管
- startRun 不再无条件 cancel：仅同 runId 重入才取消
- handleAcceptedRunEvent / postTerminalOverlay 改按 runId 查身份；
  非主任务跳过全部 overlay 更新（事件仍经 eventSink 推给 UI 进程）
- postTerminalOverlay 移除自身后，若自己是主任务则把浮层让给下一个
- executeRun 的 shouldUpdateHost==false 分支补上无条件摘除，避免泄漏
- attachRun / cancelRun 改按 runId 精确取，不再只认「那唯一的一个」
- onDestroy 取消并清空全部会话

UI 侧（AgentAppState）：
- 拆 currentRunId 的双重语义：
  observedRunIds（有没有在跑）+ latestRunId（最近启动的谁）
- 新增 hasActiveRun / stopRun(runId)；stopCurrentRun 改为按会话反查 runId，
  不再停「最近启动的那个」（并发后那是别人的任务）
- sendQueuedMessageNow 只取消本会话的 run

本次不动：无障碍/浏览器/Frida 串行化（第 2 批）、overlay 多任务展示（第 3 批）。
验证目标：两个对话能同时跑终端命令。
